# M2.3：一步问答（自动选择来源）

新增可选接口 POST /api/v1/knowledge/assistant/ask，输入 JSON：

```json
{"question":"上传过程中如何保证完整性？","consent":true}
```

仅当管理员启用了 M2.1 Chat 模型且用户在**每次调用**时明确同意资料和问题发送时，页面显示“一站式资料问答”功能。每次提交（包括错误）自动取消授权勾选。问题长度限定 4–100 字符。

服务端首先使用 M2.2 混合检索；若未启用 Embedding，则降级现有关键词检索。至多自动选取 4 个结果，作为不可变 userFileId + generation + chunkIndex 指针交给 M2.1 的 GroundedAnswerService。模型收到内容前再次检查实时权限，返回后重新验证**所有发送的来源**，包括未引用的来源。回传引用 [S1] 等跳回原文；没有候选时不调用 Chat 模型，返回“资料不足”。

此能力不是全量统计、可靠性证明或无权限的 Agent；本阶段仍没有给模型任何文件修改工具。用户自行核对引用原文。

配额：新端点与 /assistant/answer 使用相同的 Redis 用户令牌桶。它不是 Token 消耗硬预算，管理员仍应在模型网关设置价格/令牌配额。没有实现对外部调用的审计账单或生产级成本治理，尚需独立验证。单次自动查询最多可能执行一个 Embedding 与一个 Chat 请求。

默认无模型时旧页面、下载、原关键词检索全部保持不变。验证门禁为 GitHub Actions 的 Maven verify、npm run build，以及后续实际模型端到端联调。
