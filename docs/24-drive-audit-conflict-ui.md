# M3.3：网盘操作审计与冲突交互

## 操作审计

现有 OperationAuditFilter 为业务 API 的 POST/PUT/PATCH/DELETE 记录调用成功情况、响应耗时、用户上下文。M3.3 将常见 Drive 操作规范为固定枚举名：
- DRIVE_MKDIR、DRIVE_RENAME、DRIVE_MOVE
- DRIVE_RECYCLE
- 其他 API 沿用低基数 area_method 分类

新 GET /api/v1/drive/audit 只返回当前登录账号最近 30 条已规范化的网盘操作日志（类型、是否成功、耗时、时间）。不提供管理员横向查询，也不会将请求 JSON、文件正文、具体目录 ID 和分享密钥回显给用户。历史旧审计行因 op_type 分类不同不会自动迁入新视图，不伪造历史审计结果。操作日志写入继续使用原独立的尽力而为写法：审计故障不会让原网盘写入失败，但运维系统需要关注 OperationAuditService 的持久化失败日志。

## 同目录命名冲突提示

客户端支持 M3.2 的 HTTP 409 / 业务码 300004，明确提示“此目录已有同名文件或文件夹，请改名或选择其他位置”。用户手动新建、改名、移动时，原本在请求失败后就自动关闭的表单/对话框会保留，便于修正输入再提交。服务端仍由 Flyway V13 的唯一索引真正阻止并发重名。

这一阶段不会通过客户端逻辑绕过数据库重名约束；上传/分享自动重命名的后缀规则继续有效。生产系统仍须先核对 V13 历史重名并完成迁移，代码合并不等于数据库已升级。

## 验收边界

- GitHub Actions 运行完整 Maven verify、React 构建、评测脚本测试。
- 新增固定审计类型的回归，防止用户 file ID 混入审计标签。
- 新的操作日志视图是只读摘要，不是完整的不可篡改合规账本。未来若需监管级审计，还需事件版本、事件签名、防篡改存储、关联业务交易 ID 与外部留存策略。
