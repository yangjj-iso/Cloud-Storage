# M4.0：AI-Native 云存储工作台——首批产品化交付

> 本里程碑的目标不是添加会自主修改用户文件的万能 Agent，而是把 M2.0–M3.9 已验证的知识检索、授权问答与受控整理真正接入用户主导航，并建立权限一致的多文档研究工作流。

## 1. 交互入口与体验

- 桌面侧边栏增加 **AI 智能工作台**，移动端顶部导航也能访问；已有上传/云盘/文件/回收站/管理功能保持原样。
- 桌面全局 **Ctrl/⌘ + K** 切换至 AI 检索并聚焦输入框；不自动搜索，也不向任何模型发送数据。
- AI 首页展示当前账号最近一页最多 20 份资料中的就绪/待索引数量、是否已启用聊天/语义模型、最近资料、常用研究问题。**首页数据明确为一页样本，不是全局总计**。
- 分成「工作台首页」「搜索与问答」「资料准备」「整理记录」四个页面：不再要求用户知道隐藏的 KnowledgeWorkspace 组件路径。
- 搜索页沿用可信的用户名下文件 ACL、语义索引状态、精确关键词/混合检索降级说明、逐次授权的问答、引用核验、AI 批量移动预览和条件撤销。

### 文件准备流程

资料准备页从用户权限约束的 `GET /api/v1/knowledge/documents?page=...` 列出文件，筛选 `NOT_INDEXED` 和 `FAILED`，最多选择 8 份。提交前本地二次确认，服务端做完整校验，不产生任何 AI Provider 请求。

```http
POST /api/v1/knowledge/documents/index/batch
Content-Type: application/json
Authorization: Bearer <user-token>

{"userFileIds":["101","102"]}
```

- 使用十进制 **字符串** 而非 JavaScript 数字传输 `userFileId`，避免 MySQL BIGINT 超过 2^53 后丢失精度。
- 后端校验数量 1–8、唯一性、格式/64-bit 范围；每个条目都需要当前用户活跃引用、原文件 AVAILABLE、允许解析的 MIME。
- **先逐个授权全部条目，之后才插入 `knowledge_document` 和事务性 Outbox**。其中一个条目过期、被删除、属于他人或不支持，就拒绝整批；`@Transactional(rollbackFor=Exception.class)` 保证 DB 原子边界。
- 返回 `{"accepted":N,"maxBatchSize":8}` 是请求已受理/检查的份数，不等于实际新排队数量或解析成功数量。重试调用仍遵守既有的失败重试冷却与去重策略。
- 这是文本提取索引，不自动进行 Embedding。逐文件语义索引和问答仍要求当次明确授权。

### 多文档研究摘录

搜索结果可选最多 12 个片段，点击「验证来源」「复制引用」「导出 Markdown」：

```http
POST /api/v1/knowledge/research/brief
Authorization: Bearer <user-token>
Content-Type: application/json

{"sources":[{"userFileId":"101","generation":2,"chunkIndex":0}]}
```

- 这不是让模型总结，而是**原文摘录**。后端 `ResearchBriefService` 必须对每个用户逻辑文件 ID / 精确解析版本 / 精确片段号调用 `KnowledgeService.source`，重新验证用户权限、文件仍活跃及已完成完整性校验，最多 12 个且拒绝重复引用。
- **全有或全无**：任意引用被撤权、进入回收站、被替换或版本变旧，全部导出失败，不返回先前片段；不会根据浏览器传回的正文生成输出。
- 客户端复制/下载时会**再次请求后端复核**，防止仅使用「上一次已验证」的页面缓存。
- Markdown 只包含限制长度的准确引文、文件名、解析版本、片段序号和字符偏移；附带明确的「不是 AI 结论、需核对原文」说明。浏览器本地生成文件，服务器不储存摘录，也不发送第三方。
- 检索仍最多显示 20 个匹配片段；研究摘录只覆盖用户实际选择的 12 个，**不能推断已找遍所有文件或资料**。

## 2. 安全边界

| 场景 | M4.0 约束 |
| --- | --- |
| 跨租户批量建索引 | 首次写入前对整批所有用户逻辑文件 ID 完成 ACL 校验，任何一个无权限即拒绝 |
| 活跃分享与文件删除 | 以当前用户的 `user_file` 活跃引用为真相，不依赖原文件物理 `file_id` |
| 大整数文件 ID | API 采用规范的字符串格式（不接受前导零、负数或越界） |
| 原文摘录 | 每段必须在导出时重新授权并检查准确 generation；无模型调用 |
| AI 模型调用 | 知识解析无需模型；Embedding 索引/问答仍是用户独立明确授权，无批量隐式开启 |
| AI 文件操作 | 仍由 M2.8–M3.3 的预览、冲突检查、逐项确认及审计负责，不存在自动整盘移动 |
| 隐私 | 不将资料、模型密钥或用户 ID 写入 Prometheus 指标或公共页面；研究摘录仅供当前登录浏览器下载 |

## 3. 回归与验收

```bash
mvn -B verify
cd cloudchunk-web && npm ci && npm run build
python3 -m unittest discover -s deploy/release/tests -v
```

新增 Java 单测验证 ResearchBriefService 拒绝重复/越界引用、任意一个被撤权就拒绝整份摘录。MySQL Testcontainers 集成回归验证用户与其他账号共享物理对象时的逻辑 ACL、批量索引在无权文件混入时不发生写入、撤销活跃文件引用和版本变更会导致摘录不可生成。CI 仍包括其他稳定性与备份恢复检查，不会触及真实用户文件。

### 人工体验验收矩阵（部署到独立测试环境）

1. 登录普通用户，打开 AI 工作台，确保显示的是**该账号**可访问的资料，而不是其他用户的文档。
2. 从上传中心切到 AI，使用 Ctrl/⌘ + K 和移动端导航，确认搜索不会偷偷发起模型调用。
3. 准备 1–8 份支持格式的文档，选择其中一个他人或刚撤权的逻辑文件 ID 混入 API 请求，确认全部失败、后台没有新增任务。
4. 关键词搜索查看来源，勾选多段证据后复制或下载 Markdown；当搜索后将某文件移入回收站，复制/导出应整单失败，不保留旧结果。
5. 单独开启语义索引授权并验证模型请求预算/降级提示；整理建议逐项确认，过期建议不可应用。
6. 退出登录后重新进入，确认首页/搜索结果/摘录缓存不跨账户保留。

## 4. 仍待推进

当前是 **AI-Native 入口与可审计研究工作流第一版**，尚未交付完全自主的 Agent、多文件自动总结、持续自动分类、OCR 图片识别、长期跨会话 Agent 记忆、全盘向量语义搜索和工作流自动运行。它们都需要新的预算、来源版本化、细粒度授权、安全隔离、回滚/审计设计，不能因为前端有按钮就宣称完成。
