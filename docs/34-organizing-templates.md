# M4.2：智能整理规则模板与可审计的冲突模拟

> 这是确定性规则模板与逐项人工确认执行，而不是无人值守的 AI 自动整理。规则保存和模拟均不请求第三方模型；文件移动只有在特定步骤被单独批准、再次确认并通过服务器实时校验后才发生。

## 一、用户体验

在 **AI 智能工作台 → 整理策略** 中：

1. 浏览本人云盘的目录树，从现有活跃文件夹中选择目标目录；填入规则名称和文件类型：全部、文本、PDF、图片或视频，点击「保存规则」。文件不会移动。
2. 在本人文件夹内勾选最多 8 份文件，选择规则并点击「模拟冲突与影响」。切换浏览文件夹会清空选择，避免对旧选项产生误操作。
3. 系统只读验证每份文件当前归属与状态，并在事务中记录一个最多有效 10 分钟的预览快照。返回 `READY`、`NOT_MATCHED`、`ALREADY_THERE` 或 `NAME_CONFLICT`；展示符合规则数量及阻断数量。
4. 每项必须依次单独「审批本项」再「确认执行」，或明确「跳过」；不能越序推进。已审批项目不等于执行。执行前再次检查所有权、可用状态、源文件名与父目录、源文件修改时间、目标目录版本、规则是否仍有效以及同名冲突。
5. 可以取消剩余计划，但不能自动撤销已执行文件的移动。可停用规则，之后无法用其继续执行（包括旧的预览计划）；用户必须使用已有网盘操作并核对路径与权限来恢复误操作。

规则和模拟仅供当前用户查看，最多展示最近 30 条活跃规则、最近 12 个模拟计划、每个计划最近 40 个有限审计事件。规则名称存储在个人表中；审计事件只存 `SIMULATED`、`APPROVED`、`APPLIED`、`SKIPPED`、`CANCELLED`，不包含文件正文、模型回答或敏感路径。

## 二、API

所有端点需要已认证的用户会话，由 `UserContext.requireUserId()` 定位操作人；响应禁止浏览器缓存。

| 方法 | 路径（前缀 `/api/v1/knowledge/organize`） | 作用 |
| --- | --- | --- |
| `POST` | `/templates` | 创建私有规则 `{name,mimeCategory,destinationId}` |
| `GET` | `/templates` | 读取本人活跃规则 |
| `POST` | `/templates/{id}/archive` | 停用规则，需 `{"confirmed":true}` |
| `POST` | `/simulate` | `{templateId,userFileIds:["101","102"]}` |
| `GET` | `/runs`、`/runs/{id}` | 读取本人模拟计划及状态 |
| `POST` | `/runs/{id}/steps/{number}/approve` | 只批准一项，尚不移动 |
| `POST` | `/runs/{id}/steps/{number}/execute` | 明确确认一项移动 |
| `POST` | `/runs/{id}/steps/{number}/skip` | 明确跳过一项 |
| `POST` | `/runs/{id}/cancel` | 取消剩余步骤 |

`mimeCategory` 只允许 `ANY`、`TEXT`、`PDF`、`IMAGE`、`VIDEO`；使用对象实际存储的 `file_meta.mime_type` 作大小写标准化后匹配，而非相信浏览器的自报类型。规则目标必须是当前用户名下活跃的非根目录实体。

逻辑文件 ID 与目标目录 ID 均以**规范十进制字符串**提交；服务端拒绝前导零、负数、超过 signed BIGINT、重复 ID 和超过 8 份文件。由于旧 `/drive/list` 的目录 ID 仍通过 JavaScript `number` 传输，前端只允许选择 `Number.isSafeInteger` 的 ID；超出安全整数范围需要将旧目录列表接口迁移为字符串格式，这尚未实现，不能伪称已解决。

## 三、权限、数据一致性与审计

新增**追加式 Flyway V15**：`ai_organize_template`、`ai_organize_run`、`ai_organize_run_step`、`ai_organize_run_event` 四张表。数据库对同一模拟计划中的逻辑文件加唯一索引，并通过外键保护运行计划与事件连续性。

**模拟阶段**采用悲观锁读取每条当前用户名下活跃的普通文件和 AVAILABLE 物理对象。先对整组完成权限校验，之后才写入计划快照（包括文件名、来源目录、更新时间与目标目录更新时间）；任意一条文件不属于当前用户、在回收站、被删除或仍未完成校验，整组拒绝，不写入模拟记录。未匹配规则、已经在目标目录、目标有同名项则标注阻断，不发生移动。

**执行阶段**加锁确认当前用户的计划未被取消/过期、步骤已经单独批准；目标规则仍在且版本未变；再重新读取源与目标，校验源名称/父目录/更新时间/实际 MIME、目标时间及同名冲突，之后调用现有 `UserFileService.move`（其自身仍会验证目录所有权、循环路径和数据库唯一约束）。如果内容已变更、权限失效或目标目录被重命名，`execute` 拒绝、保持步骤未执行，不会自动跳过或进入下一个步骤。

执行、状态转换和审计写入位于 Spring `@Transactional(rollbackFor=Exception.class)` 中。**注意：**这里没有提供 M4.1 的短窗口「撤销」API，因为没有相同的安全撤销契约；误操作应通过原有网盘功能及人工审批恢复。计划取消也不是文件回滚。

## 四、验证与生产发布

```bash
python3 -m unittest discover -s deploy/preflight/tests -v
mvn -B verify
cd cloudchunk-web && npm ci && npm run build
```

新增真实 MySQL Testcontainers 回归检查混入其他账号的文件必须整组阻断、冲突只产生模拟结果、审批与执行分离、已批准的源文件发生后续修改就阻断、计划取消/完成不可继续执行以及动作审计数量。发布门禁 `deploy/preflight/check_release.py --phase ready` 会只读校验 Flyway V15 成功、四张表完整及 `uk_organize_run_file` 唯一索引。

生产部署前必须完成 M3.5 受控备份、批准的 V15 迁移、M3.6/M3.7 配置与恢复演练和生产等价隔离账号 E2E 操作。仅通过 CI 并不证明线上部署成功；不允许绕过 V15 门禁直接部署新 API。

## 五、下一步与局限

此版本提供**基于文件 MIME 的确定性规则**，并不分析文件语义或自动调用模型。AI 自然语言目录推荐仍在 M4.1 的受控 Agent 计划中完成。此版本不支持模板修改、基于全文内容的复杂 DSL、无限文件遍历、定时后台自动整理、多人审批、自动冲突重命名或跨文件夹大规模执行；这些都需要进一步的权限、性能与可审计设计。
