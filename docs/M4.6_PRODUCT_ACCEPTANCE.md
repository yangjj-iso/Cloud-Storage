# M4.6：AI-Native 产品体验与端到端验收

## 用户体验

受控整理的主链路为：搜索授权资料 → 选择文件与候选目录 → 明确授权生成预览 → 保存未执行建议 → 单项审批 → 再次确认执行 → 核对记录或条件撤销。

Agent 工作流提供处理进度、下一步提示、键盘焦点和移动端布局。进度包含已执行、已跳过、已撤销，不等于已移动文件数量。成功操作直接使用服务端回执更新详情，不再刷新清空整个详情。同步操作锁阻止 React 重绘前的重复提交；失败后必须先刷新权威状态，不能假设请求报错就没有执行。

批量预览最多选择 4 份文件和 12 个候选目录。切换检索结果、文件或目录会清除相应选择或本次授权；目录请求提供加载、重试、空状态和截断提示。保存计划时只提交尚未执行且未撤销的独立建议。文件执行始终逐项确认，客户端状态不能代替服务端权限、同名冲突、版本和期限校验。

## 验收分层与边界

| 验收层 | 实际执行内容 | 不代表什么 |
| --- | --- | --- |
| Node 状态逻辑 | 审批不算执行、当前步骤、终态、唯一待执行建议、同步互斥租约 | 不是浏览器或数据库测试 |
| Playwright 浏览器契约 | 真实构建页面与点击；用明确的合成 API 响应注入重复点击、拒绝确认、响应不确定、登录过期、重载、授权变化和单项入计划 | 不是服务端安全证明，不调用真实模型 |
| ProductJourneyIT HTTP | 完整 Spring servlet、认证、服务、Flyway、MySQL、Redis；双用户权限、审批与移动、取消不回滚 | 文件元数据与解析文本为合成夹具；不走上传合并/索引 worker |
| ProductJourneyIT 浏览器 | 浏览器登录 → 关键词检索 → 保存 TEXT 规则 → 模拟两份文件 → 审批一项 → 执行一项 → 取消余项 → 刷新恢复历史 → 390px 布局；请求通过本机代理进入真实 Spring API | 不验证外部模型、生产网关、MinIO、RocketMQ 全链路或生产负载 |
| 原有发布检查 | 全量 Maven 验证、质量评测、配置检查、备份恢复、依赖故障演练 | 不自动部署，也不替代人工发布批准 |

所有业务数据是一次性测试容器内的合成数据。新 ProductJourneyIT 不允许 Docker 缺失时静默跳过。常规 Maven 验证不启动浏览器子进程；专用验收显式设置 `-Dcloudchunk.browser=true`，并强制检查浏览器报告，防止未执行的浏览器路径误报通过。

本轮自动化不包含真实大文件上传、MinIO 直传、解析队列或真实模型供应商授权调用。完整生产候选验收仍需在受控 staging 中验证这些链路，不能把当前报告命名为生产全链路通过。

## 性能预算 m4.6-v1

| 指标 | 阻断阈值 | 测量口径 |
| --- | --- | --- |
| 首次同步 JavaScript | gzip ≤ 250 KiB | Vite manifest 入口与静态 imports，去重；不计 dynamicImports 为首屏 |
| 全部 JavaScript | gzip ≤ 400 KiB | dist 内所有 JS，逐文件 gzip，包含动态块 |
| 全部 CSS | gzip ≤ 80 KiB | dist 内所有 CSS，逐文件 gzip |
| 关键词搜索交互 p95 | ≤ 2000 ms | 20 次串行真实浏览器查询，从点击至响应且原文片段可见；nearest-rank，第 19/20 个排序样本 |

这些数值是版本化预算，不是已测性能成绩或生产 SLO。样本是 CI 本机、合成小数据、单浏览器、首次加后续查询；没有流量并发、移动网络限速或完整 RUM 分布。它不等同于 LCP、INP、TTFB 或大数据规模搜索性能。实际数值只能引用对应提交的 `acceptance.json`。

门禁拒绝缺失、空文件、越界或不存在的构建引用；拒绝负数、布尔值、NaN/Infinity、少于 20 个搜索样本；拒绝旧提交报告、错误作用域、缺失主链路、零测试、JUnit 失败/跳过，以及未被契约服务识别的 API 请求。不得用放宽预算、删除断言、跳过测试或替换伪造报告修复红灯。预算调整应在独立变更中附实际测量与理由。

## 运行与复现

需要 Node 22（支持 experimental-strip-types）、JDK 21、Python 3.12 和可用的隔离 Docker。只在可信本地开发环境或临时 CI runner 执行；禁止向生产 API/数据库传入测试夹具。

在仓库根目录：

```bash
set -euo pipefail
export ACCEPTANCE_SHA="$(git rev-parse HEAD)"
(cd cloudchunk-web && npm ci && npm test && npm run build)
python3 -m unittest discover -s deploy/acceptance/tests -v
python3 -m pip install -r deploy/acceptance/requirements.txt
python3 -m playwright install --with-deps chromium
docker info
rm -rf artifacts/m46
mkdir -p artifacts/m46
python3 deploy/acceptance/browser_contract.py \
  --dist cloudchunk-web/dist --report artifacts/m46/contract.json
mvn -B -pl cloudchunk-boot -am verify \
  -Dit.test=ProductJourneyIT -Dfailsafe.failIfNoSpecifiedTests=false \
  -Dcloudchunk.browser=true -Dmaven.multiModuleProjectDirectory="$PWD"
python3 deploy/acceptance/budget_gate.py \
  --dist cloudchunk-web/dist \
  --browser artifacts/m46/fullstack.json \
  --contract artifacts/m46/contract.json \
  --junit cloudchunk-boot/target/failsafe-reports/TEST-com.cloudchunk.integration.ProductJourneyIT.xml \
  --report artifacts/m46/acceptance.json --sha "$ACCEPTANCE_SHA"
```

本机代理只接受明确的 `http://127.0.0.1:PORT` 后端，不跟随重定向。浏览器屏蔽外部站点请求和 service worker，代理不记录授权头、正文或 URL。生产字体/CDN 的视觉或可用性不由该测试证明。测试账户密码只存在于一次性夹具文件与测试进程中；报告不保存密码、token、文件正文或搜索词。

## CI、证据与发布操作

`.github/workflows/release-gate.yml` 调用可复用的 `product-acceptance.yml`。它与原有配置、构建、恢复演练并行。受保护的 `live-readonly` 检查额外依赖 product-acceptance 成功，仍然需要人工 workflow_dispatch、production 环境批准和专用 runner，不会部署或修改生产。

CI 的 `ACCEPTANCE_SHA` 来自实际 checkout。PR 运行可能测试的是 GitHub 合并提交，而不是分支 head；报告必须与该次 checkout 一致。不可使用另一轮的成功产物代替当前失败结果。

`m46-product-acceptance-<run_id>` 产物保留 7 天，包含浏览器契约、真实浏览器交互采样、最终预算判定、ProductJourneyIT JUnit 证据。失败时另保留 3 天的已构建前端供复现。缺失最终报告、失败、跳过或取消的 run 都不能记为通过。

发布负责人应核对当前候选提交的整套 release-gate 成功、报告作用域与预算数值，再执行原有配置校验、备份恢复和回滚手册。仓库分支保护 required checks 属于 GitHub 管理配置；本次代码接线不等于已设置服务器端保护规则。正式候选还须补齐 staging 的上传/索引/模型供应商专项证据。

回滚本轮前端体验变更可使用上一已验证构建；本轮不新增数据库 migration。已经执行的文件移动不能通过回滚前端版本恢复；仍应走现有逐项条件撤销或经过权限验证的人工文件操作。
