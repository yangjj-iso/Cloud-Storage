# M3.2：同目录名称唯一性与跨入口并发保护

## 规则

活跃 user_file 记录以 (user_id, parent_id, file_name) 组成用户可见名称空间，包含普通文件和文件夹。MySQL V13 创建生成列 active_file_name：status=0 时为原文件名，回收站/删除时为 NULL，并建立唯一索引 uk_drive_active_sibling。索引跟随表当前的 utf8mb4_unicode_ci 校对规则（不区分大小写，某些字形也按此校对规则折叠）。该规则是在底层 MySQL 中实施的，不会因为 API/Worker 多实例的并发请求而绕过。

- **明确指定名称/位置的操作**（新建文件夹、用户主动重命名、移动、回收站还原，以及使用现有网盘业务的 AI 重命名/归类/撤销）：出现同目录重名即拒绝，错误码 300004 / HTTP 409，不会自动覆盖、删除或改掉别人的文件名。还原涉及目录树；其中任何子节点冲突会回滚整次还原，不会部分恢复。
- **自动写入文件的操作**（上传/秒传完成后的网盘挂载、共享文件转存）：保留原始名称，如被其他活跃文件/目录占用则尝试后缀“ (1)”、“ (2)”等，上限 100 次；保留扩展名，避免覆盖。分享转存的文件夹名称也使用同一自动后缀规则。真正的唯一性由 MySQL 索引而不是“先查询再插入”保证。
- 回收站记录不占用活跃名称；删除或移入回收站释放名称槽，还原时按同一规则重新争取名称，可能需要先处理占用者。
- 命名输入要求 1–512 字符；拒绝首尾空白、路径分隔符、控制字符及点路径，不能将带路径的模型文本当成文件名。

## 上线前必须处理的历史数据

**迁移 V13 会在仍存在同目录活跃重名的情况下失败，且不会自动重命名任何用户文件。** 这是刻意的安全策略：直接重命名历史数据会破坏用户现有的文件定位、分享语义和应用引用。部署升级前，请先只读运行以下检查，尤其关注英文大小写、Unicode 校对折叠：

    SELECT user_id,parent_id,
           MIN(file_name) AS representative_name,
           COUNT(*) AS conflicting_rows,
           GROUP_CONCAT(id ORDER BY id) AS user_file_ids
    FROM user_file
    WHERE status=0
    GROUP BY user_id,parent_id,file_name COLLATE utf8mb4_unicode_ci
    HAVING COUNT(*)>1
    ORDER BY user_id,parent_id,representative_name;

将结果交给文件所属用户决定保留哪个原名，对其余文件使用人工重命名或移动。处理完后再次运行查询，确认没有冲突，方可运行 Flyway V13。生产数据库先做备份、演练迁移；执行 ALTER TABLE ADD STORED GENERATED COLUMN 及唯一索引可能需要维护窗口。不要直接删除重复文件记录、覆盖对象或随意修改 file_id。

V13 使用 VARCHAR(512) active_file_name 生成列和索引，在 utf8mb4 下组合索引长度小于 MySQL 8 InnoDB 上限；先在与生产一致的 MySQL 8 版本执行演练。旧文件本身、MD5、对象存储 Key、容量和引用关系不受迁移内容修改。

## API 行为与兼容性

- 旧 DriveController API 路径不变。返回已存在的 R 错误结构，冲突使用 300004，HTTP 409；前端旧客户端只需显示错误信息即可。
- AI 模型没有文件系统的直接执行工具，仍要走 UserFileService.rename/move，所以它们也受同一 MySQL 唯一索引约束。
- 显式建目录 mkdir 与分享转存的自动 mkdirImported 是分开的；手动意图不被默默改名，自动导入才会加后缀。
- 如果某个导入需要超过 100 次重名重试，会返回冲突错误，业务事务应自行回滚并提示用户清理目录。

## 回归验证

真实 MySQL 8 Testcontainers 集成测试涵盖：Flyway V13 唯一索引真实存在、大小写不敏感重名、手工建目录/重命名/移动/回收站还原冲突、自动上传及分享后缀、24 路并发目录创建恰有一个成功、12 路并发上传自动后缀没有重复。测试同时验证普通不同用户/不同目录的同名文件仍可共存。

这不是全局文件树规范化或路径大小写跨平台一致性的证明；请根据浏览器和目标存储客户端的 Unicode 语义制定更详细的跨平台命名策略。重点是所有路径先共同服从数据库级名称唯一规则，后续再逐步解决其他元数据并发问题。
