# M4.8：真实浏览器上传与 CORS 路径验收

## 与 M4.6 / M4.7 的关系

M4.6 保留浏览器工作台与预索引夹具的测试。M4.7 保留独立 HTTP 直传、代理上传及真实队列消费者链路。M4.8 额外让 **同一候选版本构建的产品页面**在 Chromium 内登录，通过真实文件 input、产品 MD5 Worker、上传调度器与 fetch 发起上传，再复用 M4.7 的校验、索引、权限隔离与人工审批语义检查。

本轮不会部署 Staging、改变生产 CORS、调用外部模型或自动设置 GitHub 环境审批。

## 两条不能相互替代的浏览器证据

测试专用容器内，前端静态构建分别通过 `http://127.0.0.1:8765` 和 `http://127.0.0.1:8766` 提供；同源 API 代理的唯一上游硬编码为 `api:8080`。对象存储是独立 origin `http://minio:9000`。这两个环回端口不发布到宿主机。

独立 Compose 内的 MinIO 兼容服务仅允许第一个 origin，第二个故意不允许：

| 路径 | 必需观测 |
| --- | --- |
| 允许来源，5 MiB + 4096 字节 | 原生预检；2 次 PUT 成功；2 次确认；0 次代理分片；1 次合并 |
| 不允许来源，小文本 | 原生 CORS 拒绝；0 次 PUT 成功；0 次确认；产品自动降级后恰好 1 次代理分片；1 次合并 |

两条路径均必须通过实际 UI 登录，上传必须是新的 `UPLOAD` 会话而非秒传。仅有“上传完成”不算直传证据：正向路径发生代理降级会失败，负向路径没有明确 CORS 拒绝也会失败。CDP 的 `corsErrorStatus` 用于区别来源校验与 DNS、网络中断、服务端错误或浏览器私网访问限制；这些其他错误不能冒充 CORS 白名单生效。

**CORS 不是身份认证或授权边界。** 拥有有效签名 URL 的非浏览器客户端不受浏览器同源策略限制；负向浏览器在登录后通过受认证的同源 API 代理上传也仍然合法。鉴权与跨账号隔离继续由后端和 M4.7 必需阶段检查。

网络观测仅输出计数。对象存储请求不得携带应用 Bearer、Cookie 或代理认证头。不保存 HAR、trace、浏览器 storageState、签名 URL、密码、请求正文或原始异常。没有 `page.route` / mock 响应，也没有关闭浏览器 Web 安全或忽略 CORS 的开关。

## 校验、清理与版本绑定

浏览器队列的合并完成不等于异步整文件 MD5 校验通过，UI 文案已明确区分。测试独立等待真实 Worker 将文件置为 `AVAILABLE`，下载后核对 SHA-256，等待实际索引，再验证检索隔离、预览、审批不移动、单项执行、取消余项不回滚及重读。

浏览器上下文先关闭，才清理已收到回执且仍匹配本轮随机名称的条目。失败或缺失回执不能通过前缀扫描删除；继续使用 M4.7 的软删除、空目录检查与会话注销。`cleanup: complete` 不代表回收站、审计或所有物理对象被抹除。Docker 作业结束还必须完成本次独占项目的容器与匿名卷清理。

前端构建与后端 jar 均来自当前 checkout（PR 包含实际合并快照）。前端镜像内保存 40 字符版本标记，必须与 API identity 和报告提交一致。这是构建绑定，不是供应链签名。

`browser.json` 的 `scope` 为 `browser-upload-cors`，`mode` 保持 `isolated`，`model` 必须为 `not-requested`。报告在构建/服务启动前失效旧成功，运行器启动再次覆盖。十二个 M4.7 阶段及原预算全部保留，另加浏览器版本、两次 UI 登录、零页面异常、逐路径传输计数校验；布尔值、缺失计数、跳过、路径替代和凭据泄漏不能过门禁。

## CI 与复现

`staging-acceptance.yml` 的隔离作业在原 HTTP 旅程后执行真实浏览器，并在宿主机再次校验报告。M4.8 失败会阻断该作业及已有发布依赖，不替代 M4.6 或 M4.7。浏览器仅使用测试镜像，Python Playwright 与镜像均固定为 1.57.0；不安装到生产镜像。

仅在可信临时 Docker 主机上，从干净 checkout 执行：

```bash
set -euo pipefail
export COMPOSE_PROJECT_NAME="cc-m47-local-$(date +%s)"
export M47_IMAGE_TAG="$COMPOSE_PROJECT_NAME"
export M47_ENVIRONMENT="m47-local-$(date +%s)"
export M47_EXPECTED_SHA="$(git rev-parse HEAD)"
export M47_REPORT_DIR="$PWD/artifacts/m48-local"
python3 deploy/acceptance/browser_upload_gate.py --initialize \
  --report "$M47_REPORT_DIR/browser.json" --sha "$M47_EXPECTED_SHA" --environment "$M47_ENVIRONMENT"
python3 -m unittest discover -s deploy/acceptance/tests -v
(cd cloudchunk-web && npm ci && npm test && npm run build)
mvn -B -pl cloudchunk-boot -am package
docker build -f deploy/acceptance/Dockerfile.runtime --build-arg REVISION="$M47_EXPECTED_SHA" -t "cloudchunk-m47:$M47_IMAGE_TAG" .
docker build -f deploy/acceptance/Dockerfile.browser --build-arg REVISION="$M47_EXPECTED_SHA" -t "cloudchunk-m48-browser:$M47_IMAGE_TAG" .
trap 'docker compose -f deploy/acceptance/compose.yml down --volumes --remove-orphans' EXIT
bash deploy/acceptance/start-isolated.sh
docker compose -f deploy/acceptance/compose.yml run --rm --no-deps acceptance
docker compose -f deploy/acceptance/compose.yml run --rm --no-deps browser
python3 deploy/acceptance/browser_upload_gate.py --report "$M47_REPORT_DIR/browser.json" \
  --sha "$M47_EXPECTED_SHA" --environment "$M47_ENVIRONMENT"
```

## 不能由本轮推断的结论

只覆盖此隔离拓扑、指定浏览器和合成数据。并不证明已部署 HTTPS 网关、生产 CDN、实际公网证书/域名、WebSocket 转发、Safari/Firefox、断网续传、GB 级并发压测或真实模型通过。浏览器上传后整理步骤复用 HTTP 断言，不能宣称整段工作流都由浏览器操作。大文本显式 `PARTIAL` 仍只是部分索引。

下一层受控 Staging 应单独核对实际前端与签名 URL 可达性、HTTPS、反向代理不改写签名 host/path/query、部署实例和桶级 CORS 覆盖规则、精确来源白名单与回滚。不要把本测试的环回 origin 或实例全局配置直接复制到生产。

参考：Playwright 文件上传（https://playwright.dev/python/docs/input#upload-files）、测试 Docker 镜像（https://playwright.dev/python/docs/docker）、Chromium Network.loadingFailed（https://chromedevtools.github.io/devtools-protocol/tot/Network/#event-loadingFailed）、对象存储 CORS（https://docs.min.io/aistor/administration/cors-configuration/）及 Silo 兼容性说明（https://silo.pgsty.com/zh/compatibility/migration/）。
